# Project Brief: "Monarch" - Location-Based Social Discovery App

## Objective
Build a mobile-first Progressive Web App (PWA) or full-stack web application called "Monarch." The app gamifies real-world exploration by allowing users to permanently claim Points of Interest (POIs) as their "Kingdom" by submitting an AI-verified live photo and review. 

## Technical Stack
- **Frontend:** React (Next.js App Router or Vite), Tailwind CSS, Lucide React (for icons)
- **Mapping:** Mapbox GL JS or Google Maps API
- **Backend/Database:** Supabase (PostgreSQL, Auth, and Storage for photos)
- **AI Integration:** Google Gemini API (Structured Outputs) for real-time text and image validation

---

## Core Features & Architecture

### 1. Dual-Tab Mapping System
- **Community Tab:** A global map showing every user. There is only ONE permanent Monarch per location globally. Gray markers for unclaimed spots; crowned colored markers for claimed kingdoms.
- **Friends Tab:** Filters the map to display ONLY the user and people they follow. Inside this inner circle, whoever claimed the spot first among friends is crowned the Monarch of that circle.

### 2. The "Claim Crown" Flow & AI Gatekeeper
- When a user is within a specific radius of an unclaimed POI, they can hit "Claim Crown."
- They must take a live photo (simulated via camera input) and write a short review.
- Before saving to the database, the data is sent to the Gemini API using structured JSON output to evaluate quality:
  - **Image Check:** Ensure it isn't blurry, pitch black, or a low-effort duplicate.
  - **Text Check:** Ensure the review is substantive (minimum 1–2 sentences, helpful insight) and free of profanity.
  - **Response:** If approved, save to database. If rejected, return a stylized "Royal Guard" error message explaining why (e.g., "The review is too brief for a Monarch!").

## Database Schema (PostgreSQL / Supabase)

Please generate the migrations or database schema for the following tables:

### `profiles`
- `id`: uuid (references auth.users)
- `username`: text (unique)
- `avatar_url`: text
- `created_at`: timestamp

### `locations`
- `id`: text (Primary Key, matches Mapbox/Google POI ID)
- `name`: text
- `latitude`: double precision
- `longitude`: double precision
- `category`: text (e.g., 'cafe', 'park', 'restaurant')

### `claims`
- `id`: uuid (Primary Key)
- `location_id`: text (references locations.id)
- `user_id`: uuid (references profiles.id)
- `photo_url`: text
- `review_text`: text
- `created_at`: timestamp
- *Constraint:* Unique index on `location_id` to guarantee only one global claim exists per location.

### `friendships`
- `id`: uuid
- `user_id`: uuid (references profiles.id)
- `friend_id`: uuid (references profiles.id)
- `status`: text ('pending', 'accepted')
